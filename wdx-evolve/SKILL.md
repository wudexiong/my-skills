# wdx-evolve — 技能/流程自进化

**触发**：技能不灵了 / 效果差 / 发现可复用改进 / 用户说"这个技能不好用" / 定期健康检查。

## 原则

- **模型冻结，进化技能和知识**（EvoSkill 模式）——不改 AI，改 SKILL.md + knowledge
- 改进必须**可验证**：改完要能证明"之前不行，现在行"
- 不达标的不进——改进也要过"跨任务可复用"标准

## 流程（迭代循环，借鉴 Skill Creator v2）

### 1. 诊断
- 找出问题技能/流程：是描述不清（不触发）？步骤错（结果差）？缺场景（没覆盖）？
- 记录"失败证据"：哪里没达到预期

### 2. 改进
- 编辑对应 SKILL.md（`D:\tools\skills\<name>\SKILL.md`）
- 三类改进：
  - **描述优化**：description 不够精确 → 该触发时不触发
  - **步骤修正**：流程有 bug / 顺序错
  - **知识补充**：缺场景 / 缺领域知识 → 从 knowledge/wiki 补

### 3. 重跑验证
- 用改进前失败的那个场景重跑一遍
- **必须有证据**：之前失败 → 现在成功
- 无法验证的改进 = 不提交

### 4. 提交（版本管理）
- 更新 `skills-lock.json` 的 hash（`node scripts/reindex.mjs` 自动）
- 版本号 +1（SKILL.md frontmatter `version:`）
- commit message: `evolve(<技能名>): <改了什么>`
- push → 全局 junction 自动生效

## 自进化触发点（自动）

| 时机 | 动作 |
|---|---|
| 技能调用后效果差 | 用户/agent 标记 → 走本流程 |
| wdx-init 某步卡住 | 记录卡点 → 改进对应步骤 |
| 知识回流积累 | digest 后定期 review wiki → 是否要固化成技能 |
| 定期（每周） | 健康检查：技能清单 vs 实际使用，废弃不用的 |

## 反模式

- ❌ 为改而改（没验证就提交）
- ❌ 把项目特有经验硬塞进通用技能
- ❌ 一次改太多（小步快跑，一次一个改进）
