# wdx — 唯一入口（一条路由，包圆一切）

用户只需要说 **"wdx 我要做 X"**，本技能负责：**判断场景 → 分流到对应工作流 → 全程跟随直到交付。**

## 分流表（核心）

| 用户说 | 场景 | 走哪个工作流 |
|---|---|---|
| 新项目 / 新功能 / 新想法 / 大改造 | 构建 | **wdx-init**（初始化全流程） |
| 太大太模糊 / 跨多会话 / "不知道从哪开始" | 大任务 | **wayfinder**（画决策地图） |
| "有 bug" / "坏了" / "报错" | 修 bug | **wdx-debug**（triage → diagnosing → TDD） |
| 外部来的 issue / 别人的 PR | 收外部 | **triage**（状态机，状态在 Issues） |
| 要发布 / 上线 / 打版本 | 发布 | **wdx-release**（版本 + changelog + PR + CI） |
| 做完了 / 收尾 / 归档 | 收尾 | **wdx-archive**（归档 + 经验回流） |
| 换会话 / 交接 | 交接 | **handoff** |
| 不确定 / 都没对上 | 兜底 | **wdx-init**（或先问一句） |

## 执行原则

- **一次只走一条工作流**，专注；切换场景时重新调用本技能
- **先加载对应 SKILL.md 再行动**——不凭记忆执行
- 需要人确认的（设计定稿、发布、高危操作）**必须停下等确认**，用 grilling 的"推荐答案 + 等待"模式
- 状态放 GitHub Issues（triage 标签就是状态），不另搞状态文件
- 技能库/工作流更新：`skills-update` 自动同步上游最新版

## 失败处理

- 工作流某一步挂了 → 报告卡在哪一步，建议下一步（继续/回退/换方案）
- 用户不确定场景 → 用 grilling 问清再走
- 不需要本技能的任务（闲聊、单文件小改）→ 直接做，不套流程
